# S7 事件驱动会话、中断与恢复

在终端已经显示半句回复、模型连接仍挂起时，用户发来了中断。此时会话必须能读到下一条操作。另一次启动时，日志里可能已有一次创建文件的工具调用。恢复应让模型看到当时的结果，并让磁盘上的文件保持原貌。这两个场景分别检验会话控制和历史持久化。

## 谁拥有历史

```text
前端 ── Op ──▶ Session 单写者 ── 借用历史 ──▶ AsyncLlmClient
                  │         ◀── 增量和完整的 ModelTurn
                  ├── ToolRegistry ──▶ 工具观测
                  ├── 消息按顺序追加到 RolloutStore
前端 ◀─ Event ────┘
```

`Session::spawn` 接收会话依赖的所有权，建立输入和事件通道，再返回 `SessionHandle`。调用方可以克隆操作发送端，接收端由一个前端消费。`Op` 只在进程内传递。`Event` 使用 `type` 标签，能单独编码成一行 JSON。S1 的 `Message` 仍是唯一的上下文模型。界面的数个 `TextDelta` 最终可以对应一条助手消息。

`SessionMode::New` 从空历史和新路径开始，已有非空日志应报告错误以免串入另一段对话。`Resume` 开始时读取既有日志，将有效记录重放为历史，然后受理新输入。恢复出错时发出 `Error` 并关闭事件流。记录里即使保留工具名和参数，恢复也只复制消息。

## 中断必须能赶上正在运行的一轮

`spawn` 拥有操作接收端和唯一一份可写历史。空闲时接收 `UserTurn`，为该轮创建独立的 `CancellationToken`。进入一轮以后仍要同时轮询操作通道和本轮 future，收到 `Interrupt` 就取消当前 token。活动轮期间到达的新输入可按接收顺序暂存，终态之后再启动。空闲时的中断可以忽略。操作通道关闭时通知活动轮取消，退出写者并释放事件发送端。

`run_turn` 接收当前历史的独占借用。先发 `TurnStarted`，记录用户输入，随后按 `max_steps` 驱动 S6，并把文本回调即时转成 `TextDelta`。模型给出工具调用时，先记录带原始调用 ID 的助手消息，再发 `ToolCallBegin`。工具成功与失败都产生 `ToolResult` 和带相同 ID 的 `ToolCallEnd`，供下一次采样使用。完整最终答复写入日志后才发送 `TurnCompleted`。

采样等待期间要能因取消而结束，即使服务端一直没有发出下一个字节。取消后发一次 `TurnAborted`。已经发出的零散文本仅供界面显示。会话错误和采样步数耗尽走 `Error`。完成、中断、错误是互斥的三个终态。同步工具有自己的超时边界，安排其阻塞工作时要让调度任务仍能接收中断。正在执行的同步工具到达可收尾的位置时，先记录已经发生的结果，再结束该轮。

## 日志格式与坏行计数

`RolloutStore::append` 接受一条 S1 消息记录，每次追加一行 UTF-8 JSON 并写行尾换行。消息内部的换行由 JSON 转义。下面是只有一条用户消息的日志。

```json
{"message":{"User":"请继续"}}
```

`RolloutStore::load` 逐行检查，保持有效记录的顺序。空白行、坏 JSON、字段结构错误均各计入一次 `skipped_bad_lines`。完整的最后一条记录即使没有行尾换行也可读取。零字节文件返回 `EmptyFile`，读取故障返回 I/O 错误。一份非空但只有坏行的日志会返回空记录和实际跳过行数。`RolloutLoadResult::replay` 从这些有效记录恢复历史，保留工具结果、错误标记和调用 ID。

## 验收

完成 S2、S6 依赖和本阶段的五处练习后运行 `./x.sh s7`。恢复测试使用一个计数工具，直接检查新请求包含旧历史且计数仍为零。中断测试用一条可观察的文本增量证明采样已经开始，然后让模型一直等待。收到中断后同一个句柄还能跑第二轮。这个顺序能检出只能在两轮之间处理输入的实现。
