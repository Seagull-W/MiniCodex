# S2 工具注册表与 Shell 执行

S1 的模型发出一条 `ToolCall` 后，只知道工具名称和 JSON 参数。S2 由注册表找到对应的实例。比如 `{"argv":["printf","%s","你好"]}` 交给名为 `shell` 的工具后，工具把输出交回 S1，由 Agent 用原来的 `call_id` 写入历史。

## 一个注册表，两条调用路径

| 调用方 | 入口 | 可观察结果 |
|---|---|---|
| 模型适配层 | `ToolRegistry::specs` | 当前所有工具的名称、用途及参数 Schema，按名称升序排列 |
| S1 的 `Agent<C, ToolRegistry>` | `ToolExecutor::execute` | 目标实例收到完整的 JSON 参数，成功或失败均沿用 S1 的返回类型 |

注册表持有 `Box<dyn Tool>`，因此实际类型不同的工具可以放在同一张表里。名称取自工具自己的 `spec()`。重复注册同名工具时，后注册的实例同时接管描述和调用。导出的列表应独立于 `HashMap` 的遍历顺序。

## 五处练习

1. `ToolRegistry::register` 接管工具所有权，建立名字到实例的映射。
2. `ToolRegistry::specs` 生成排好序的描述列表。参数 Schema 随描述一同交给模型。
3. `ToolRegistry::execute` 接收 S1 借出的 `&ToolCall`。考虑参数从借用的历史记录传到拥有 `Value` 的工具时，哪里需要复制。已知工具的错误原样交回，未知工具的错误写明名称。
4. `truncate_utf8_output` 返回预算内最长的完整前缀。例如「你好!」共 7 字节，额度 4 时只能保留「你」。额度为 0 时返回空串。
5. `ShellTool::call` 校验参数、启动进程、收集输出，统一处理超时和退出状态。

骨架与行为样例见 [tools.rs](../../src/tools.rs) 和 [s2_tools_and_shell.rs](../../tests/s2_tools_and_shell.rs)。

## 子进程的契约

输入中的 `argv` 是非空字符串数组，首项为非空的程序名，其余字符串逐项传入。用 `cwd` 作为工作目录，每个参数只解释一次。测试需要控制两条输出流和退出码时，会显式选择 `sh` 为程序，用固定脚本作为参数。

同时收集 stdout 和 stderr。管道容量有限，先等进程退出再读满管道可能互相等待。合并后的输出按 UTF-8 字节预算返回，超过预算时仍需处理管道里的剩余字节，让子进程有机会退出。只有标准输出时，调用方直接读到原文。

退出码为零返回 `Ok`。非零返回 `Err`，包含退出状态及已捕获的诊断。超时后终止并回收直接子进程，错误中保留 `timeout` 供调用方识别。超时用例让进程先写出 PID，返回后既检查耗时，也检查该 PID 已消失。

## 验收与复核

```bash
./x.sh s2
```

8 个用例分别检查同步派发、未知名称、Schema 列表、UTF-8 前缀、工作目录与双流捕获、真实进程输出预算、非零退出和超时回收。进程用例使用临时目录及 POSIX 命令。复核时用一次工具错误说明它怎样回到模型历史，并指出是谁保留了原调用的 `call_id`。
